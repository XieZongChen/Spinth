# 标准流程图（Standard Flowchart）功能规格

> 本文件是 docs/13 阶段 4「常见图能力」第 1 项——标准流程图的功能锚点。
> 后续 4.2 组织架构、4.3 网络拓扑、4.4 泳道、4.5 时序、4.6 类图、4.7 BPMN
> 需要复用的底座（锚点端口、全局避障、容器、箭头族、符号注册）在此登记首发口径，
> 后续图种只做增量，不重开设计。
>
> 写法：功能视角（用户任务 → 能力地图 → 契约 → 分期 → 验收）。缺陷清单是
> 能力地图的 gap 列，不是本文的主轴。

## 1. 功能定义

### 1.1 什么算「标准流程图」

本仓库的标准流程图 = ISO 5807 风格的程序流程框图，用户用它表达
**步骤序列 + 分支条件 + 起止边界 + 跨页连接**。判定标准（四条同时满足）：

1. 图元是抽象几何符号（矩形=处理、菱形=判断、梯形/平行四边形=输入输出），不是
   领域语义对象（不是 BPMN 任务、不是 UML 类）；
2. 连线是单向流线（实线 + 单头箭头），带可选文字标签（是/否/异常）；
3. 布局由用户手工摆放 + 吸附对齐完成，无自动布局、无语义校验；
4. 一张图可独立交付：导出 PNG 或保存为项目文件后，别人能读懂流程。

### 1.2 范围内

| 维度     | 范围                                                            |
| -------- | --------------------------------------------------------------- |
| 图元     | 现有 20 型 SHAPE（不新增形状类型）、TEXT、STICKY（作注释框）    |
| 图元样式 | 填充 / 边框线型 / 边框色 / 边框宽度 / 内文字颜色与排版          |
| 连线     | STRAIGHT / ELBOWED / CURVE × 首尾独立箭头 × 线宽 / 颜色 / 虚线  |
| 连线文字 | 单一标签 + 沿路径 ratio 定位                                    |
| 锚定     | 四边锚点 + 沿边滑动参数（端口）+ 轮廓交点 + 同边多线错开 + 自环 |
| 路由     | 正交候选走廊 + 全局避障（第三方节点）+ 圆角拐角                 |
| 吸附     | 参考线（含粘滞 / 端部链）+ 网格吸附（新增）+ 对齐 6 / 分布 2    |
| 组织     | 多选 / 编组 / 层级 / 复制粘贴 / 级联删除 / 断头线清理           |
| 数据     | 撤销重做 / IndexedDB 持久化 / 多标签单写者 / 项目文件 / 只读态  |
| 输出     | 导出 PNG（选区 / 全画布）                                       |

### 1.3 范围外（明确不做，避免越界）

- BPMN / UML 语义（事件类型、网关语义、类分栏、生命线）：属 4.5–4.7；
- 容器 / 泳道 / 框架：属 4.4（本 spec 只用矩形 + 标题近似分区，见 §4.4）；
- 自动布局、自动对齐、语义校验（缺箭头、孤立节点检查）：不做；
- 线跳（line jump）、SVG / 矢量导出：列 backlog，本阶段只做 PNG；
- 协同、服务端、账号：docs/10 后置；
- 图元库 / 模板市场：不做，样本图进 E2E 夹具。

## 2. 用户任务

| #   | 任务                   | 成功判据                                                     |
| --- | ---------------------- | ------------------------------------------------------------ |
| T1  | 画一条三步直线流程     | r → 拖出三个矩形 → l 连线 → 双击线打标签 → 一键导出          |
| T2  | 画带分支与合流的流程   | 一菱形两出边（标注「是/否」）→ 两条线分别进两个矩形 → 合流   |
| T3  | 画带回边（循环）的流程 | 末端节点连回上一步骤，回边不穿过其他节点、可读               |
| T4  | 跨列长流程（子流程）   | 子过程形状 + 跨列连线带避障，不穿中间节点                    |
| T5  | 排版对齐               | 拖动落点吸附网格与参考线，多个矩形等宽对齐、间距一致         |
| T6  | 修改既有流程           | 改形状类型 / 边框 / 文本后连线跟随；插删节点后连线自动重路由 |
| T7  | 交付                   | 导出 PNG（≥2x）无裁切；项目文件另存后可复原                  |

验收样本（进 E2E 夹具与视觉基线）：

- **S1 白底黑框三步流程**：起止（stadium）→ 处理（rect）→ 判断（diamond），
  一条回边，三个标签。
- **S2 跨列审批流**：6 个节点分两列，含子过程与数据库，中间放障碍节点验证避障。
- **S3 同边多线**：两个大矩形之间三条平行线，均锚同一对边且不重叠。

## 4. 图元层

### 4.1 形状与流程图符号映射（不新增形状类型）

| 流程图语义          | 复用形状              | 说明                                     |
| ------------------- | --------------------- | ---------------------------------------- |
| 起止 / 终止         | `stadium`             | 胶囊形                                   |
| 处理 / 步骤         | `rect`、`round-rect`  | 白底黑框主用形状                         |
| 判断 / 分支         | `diamond`             | 出边文字「是/否」                        |
| 输入输出 / 数据     | `parallelogram-right` | 方向可换 left                            |
| 文档                | `document`            | 波浪底                                   |
| 子过程 / 预定义处理 | `predefined-process`  | 竖线带                                   |
| 存储 / 数据库       | `eng-database`        | 圆柱                                     |
| 连接点（页内）      | `ellipse`（小尺寸）   | 圆形连接符                               |
| 跨页连接            | `off-page`            | 尖角                                     |
| 准备 / 循环边界     | `hexagon`             | 六边形                                   |
| 手动输入 / 手动操作 | `trapezoid-up/down`   | 梯形                                     |
| 延时                | `delay`               | 半圆端                                   |
| 注释 / 说明         | `TEXT`、`STICKY`      | 形状侧新增「无填充」后也可用 rect 注释框 |

**决定**：不新增 ShapeType。理由：docs/13 §4.3 要求先审计「扩 ShapeType / 符号控件 /
图标资产」再决定承载方式；标准流程图完全可由现有 20 型表达，新增枚举会把
`ShapeTypeSchema` 与 `SHAPE_TYPE_OPTIONS` 双双膨胀却换不到表达力。后续图种若真需要
领域符号（路由器、BPMN 事件），走 docs/13 §4.3 的符号注册评估，而不是在这里预造。

### 4.2 样式契约（G-01 边框色/宽不可配、G-02 填充缺白/黑与无填充）

现状（基线）：

- 填充：`color` 单字段，6 色板（`#e8f0fb` 等，无白色、无透明）。
- 边框：`borderStyle: solid | dashed | none`；边框色 = `darkenHex(color, 0.25)` 派生
  （`shapeVm`）；边框宽恒 `STROKE_WIDTH = 1`。
- 后果：**「白底黑框」不可达**——最浅填充压暗 25% 得到浅灰边框，做不到黑框、粗框、
  无填充标注框。

编号归属：G-01 = 边框色/宽度不可独立设置；G-02 = 填充缺白/黑与「无填充」。

目标契约（schema 增量，全部 optional，老文档零迁移）：

| 字段          | 类型                                | 缺省语义                                | 消费点             |
| ------------- | ----------------------------------- | --------------------------------------- | ------------------ |
| `borderColor` | `string?`（hex）                    | 缺失 = `darkenHex(color, 0.25)`（现状） | `shapeVm` 描边色   |
| `borderWidth` | `number?`                           | 缺失 = 1；档位 1 / 2 / 4                | `shapeVm` + 细节线 |
| `fill`        | `'solid' \| 'none'`，默认 `'solid'` | `'none'` = 只描边不填充                 | `shapeVm` 填充分支 |

设计要点：

- 三字段统一由 `packages/core/src/widgets/shape/shapeStyle.ts` 提供纯函数
  `resolveShapeStyle(data)`（返回 `{ fill, fillColor, strokeColor, strokeWidth, dashed }`），
  `shapeVm.render` 的「纯平移快速路径」守卫键同步扩展（漏加会让改边框色不重画）。
- `borderColor` 一旦写入即固定，不再随填充色变化；「自动（随填充）」不提供还原选项
  ——避免「删除字段」写路径（`model.update` 传 undefined 的语义未定义），语义写进
  docs/04 §8.2。
- `fill: 'none'` 不改命中语义：`shapeVm.hitTestPoint` 走 `pointInRotatedRect`（bbox），
  无填充形状照常可选中、可拖、可连线，符合流程图注释框预期。
- 色板增补：
  - 填充 `SHAPE_PALETTE` 追加 `#ffffff`、`#000000`（共 8 色）；
  - 新 `SHAPE_BORDER_PALETTE = ['#1f2937', '#000000', '#ffffff', '#2563eb', '#dc2626', '#059669']`
    （与线色板同源风格，保证「黑框 + 灰线」的经典流程图观感）。
- 状态预设（免必配）：ActionBar 边框 popover 保持 3 态，色与宽各自独立 popover；
  不做「主题/样式预设」抽象（一次点击三次操作即可，避免过度设计）。
- 细节线（`drawShapeDetails`：圆柱上下弧、文件折角、子过程双竖线）必须跟随
  `borderWidth` 与 `borderColor`；**虚线边框时同样绘制**（现状只在 solid 分支画，
  G-10）。

### 4.3 尺寸、创建手势与撑高

- 单击创建（位移 < `DRAG_TRACTION_SCREEN` = 10 屏幕 px）：默认 `120 × 80`，以按下点
  为中心，工具保持激活、不选中（docs/04 §2）。
- 拖拽创建：过 10px 阈值后跟手，右下角随手；松手落库。
- 图形内文字撑高：`autoHeight` 默认 true，`shapeHeightFromTextHeight` 按形状内接几何
  反解；手动拖角改宽高即置 false。
- 网格吸附开启时（§9.2）：**量化左上角**（几何原点），不是中心——多元素左对齐才整齐；
  单击创建先按中心算矩形再量化左上，最多偏移 8px，可接受。

### 4.4 与分区（集群）的关系

流程图需要「这一步属于哪个系统/部门」的视觉分区时，用矩形 + 标题文字 + 编组近似
（zOrder 置底、`fill` 浅色或 `none`）。不引入容器语义（属 4.4）。docs/13 §4.3 的
「集群先用矩形 + 标题 + 分组近似」同口径。

## 5. 文本层

基线已满足，本层无需改动；契约登记如下（形状内文字样式字段见 §4.2）：

- 图形内文字：TipTap HTML 存储，渲染经 `htmlToPlainText` 测量 + PIXI 文本；
  内接矩形按形状反解（`insetRectOf`）；overflow hidden。
- 排版：`fontSize` / `textColor` / `align`（形状默认 center）/ `lineHeight`，per-实例
  optional，消费顺序「override → 控件常量默认」。
- 编辑：统一编辑会话（docs/17），空文本 keep（形状不因清空文字而删除/缩高）。
- 线标签：`LINE.text` + `textRatio`，双击线身创建，镂空分段绘制（docs/08 §6）。

## 6. 连线层

### 6.1 线型 × 箭头矩阵（M-01 收口）

| 线型       | 语义                 | 流程图用法               |
| ---------- | -------------------- | ------------------------ |
| `STRAIGHT` | 直线                 | 短距离、相邻节点         |
| `ELBOWED`  | 正交折线（R14 圆角） | 主用；分支与跨列         |
| `CURVE`    | 三次贝塞尔 S 弯      | 回边、可读性优先的长连线 |

箭头（首尾独立，值域 `none | arrow | solid | diamond`）：

| 值        | 视觉                      | 流程图语义           |
| --------- | ------------------------- | -------------------- |
| `none`    | 无                        | 无箭头连接           |
| `arrow`   | 开放箭头（±25.7°，长 10） | 流线主用（默认终点） |
| `solid`   | 实心三角                  | 强调方向             |
| `diamond` | 菱形                      | 组合/聚合的近似      |

**文档改写**：docs/08 §5 的「四种：开放箭头（45°）、内实心三角（30°）、外实心三角、
菱形」改为「三型 + none，开角 ±25.7°、长 10（`ARROW_LEN`/`ARROW_ANGLE` 单源）」。
空心三角 / 鸦爪 / 虚线依赖留 4.6 首发，本 spec 不预造。

### 6.2 线上文字

不变，引用 docs/08 §6。流程图约束：单标签；`textRatio` 默认 0.5；分支标签
（是/否）由用户在两条出线的中段分别建文字。

### 6.3 线宽 / 颜色 / 虚线

- 线宽 4 档 1 / 2 / 4 / 8（`LINE_WIDTH_STEPS`），默认 2；虚线 `dashed` 布尔；
  颜色板 6 色（与画笔同源）。
- 形状描边宽度档位（1/2/4）与本档位**不必相等**，但视觉默认值需成对协调：
  形状 1 ↔ 线 2 为既有观感基线，网格吸附与样式改动不得破坏视觉基线截图。

### 6.4 段滑移与拐点（G-11）

现状：拖线身段 = 段滑移，五点拆分保正交，落库 `{points, pinned: true}`；
`pinned` 后锚定跟随只重贴两端、不重路由（用户手滑优先）。

目标（本 spec 落地「拐点手柄」）：

- 选中 ELBOWED 线时，中间拐点显示 6 屏幕 px 方块手柄（屏幕恒定尺寸）。
- 拖单拐点：相邻两段保持轴对齐——改 X 时同步「与 P(i) 同 X 的邻居」，改 Y 同理；
  首末段（锚点段）不动。
- 命中优先级：端点手柄（12px）> 拐点手柄（8px）> 段胶囊。
- 落库单事务 `{points, pinned: true}`；手势期零 Yjs 写。
- 不做「隐藏中间拐点」（points 第三元）：无用例支撑，保留 docs/08 §9 挂账。

## 7. 锚定层（本 spec 的核心底座）

### 7.1 锚点契约

现状：`anchorOf(rect, join, rotation)` = bbox 四边中点绕中心旋转；`startJoin/endJoin`
是四值枚举。后果两条：非矩形形状锚点浮空；同边多线完全重叠。

目标契约（core 内部接口，非公共 API）：

```ts
// types/base.ts（IVmBase 追加）
/** 锚点世界坐标：join 边 + 沿边参数 t ∈ [0,1]（0.5 = 中点，缺省）
 *  θ 感知；形状覆写走轮廓交点，其余类型走 bbox 边插值 */
getAnchorPoint(join: JoinDir, t: number): IPt;
```

```ts
// types/widget.ts（LineSchema 追加，optional 零迁移）
startPort: z.number().min(0).max(1).optional(),   // 缺失 = 中点且允许自动错开
endPort: z.number().min(0).max(1).optional(),
```

实现分层：

1. 基类默认：`anchorOf(rect, join, t, rotation)`（`lineGeometry.ts` 扩展第四参，
   `t = 0.5` 与旧实现逐字节等价——回归硬断言）；
2. `ShapeVm` 覆写：`outlineAnchor(shapeType, w, h, join, t)`（§7.2）；
3. `LineAnchorFollow` 统一经 `vm.getAnchorPoint(join, port ?? 0.5)` 取点，不再直接
   调 `anchorOf`。

### 7.2 轮廓交点（G-04）

新增 `packages/core/src/widgets/shape/shapeOutline.ts`：

```
outlineAnchor(shapeType, w, h, join, t):
  1. P = bboxEdgePoint(w, h, join, t)          // 四边按 t 线性插值
  2. shapeType ∈ 解析矩形族 → 返回 P           // rect / round-rect
  3. poly = outlinePolyline(shapeType, w, h)   // 闭合折线，≤ 48 段
  4. 从 P 沿「P → 形心」方向与 poly 求交，取离 P 最近的交点 Q（多交点取最近）
  5. 无交点 → 返回 P（保守兜底）
```

为何是「P 朝形心求交」而不是「按角度参数化」：对 20 种形状统一成立且无需逐型解析；
`t = 0.5` 时 rect/ellipse/diamond/hexagon/stadium 等凸形状结果恰好等于旧 bbox 边中点
（保持既有锚点观感），只有会浮空的形状（triangle、parallelogram、trapezoid、
eng-database、eng-file/folder、document、off-page、delay）才发生位移——这正是缺陷
修复面。

**常量单源**：`outlinePolyline` 与 `shapePath.ts` 的绘制几何必须共用同一组参数
（折角、波浪、圆柱头、六边斜宽等）。实施第一步把 `shapePath.ts` 与 `shapeGeometry.ts`
里重复出现的几何常量抽到 `shapeMetrics.ts`，两边共同消费；单测断言「20 型 × 4 join ×
t ∈ {0.25, 0.5, 0.75} 的锚点落在折线 0.5px 容差内」，防路径与锚点漂移。

性能：`t` 只在路由/跟随帧计算，单次 ≤ 48 段点-线距离；先不做缓存，若 `bench.spec`
显示 reattach 超过 §15 预算，再加按 `(shapeType, w|h 量化 8px)` 的 LRU。

### 7.3 同边多线错开（G-05）

规则（`LineAnchorFollow` 内，纯派生、**不落库**）：

1. 每轮 reattach/previewFollow 先扫一遍线，按 `(nodeId, join)` 分组；
2. 组内 n > 1 且端点 `port === undefined` 的线，按**线 id 字典序**稳定分配
   `t_i = clamp(0.2 + 0.6 × (i+1)/(n+1), 0.1, 0.9)`；
3. 显式 `port` 优先，不参与分配；
4. n = 1 或未锚定 → 0.5（旧行为）；
5. **同边自环整条豁免**（二轮返工拍板）：两端同 `(nodeId, join)` 的自环不占槽、
   两端恒 0.5——否则 0.4/0.6 使锚点差 0.2×边长 ≥8px，绕过 routeSelfLoop 的
   重合展开分支、把 U 压成 0.2×边宽（120 边 = 24px ≪ 目标跨度
   `max(80, 边长×0.5)`，二轮审查实测）；自环也不挤占同边其他线的槽位。

收益与约束：

- 零写入（派生值稳定、可重算一致），因此不产生幻影事务，`samePoints` 幂等守卫继续有效；
- 用户手工拖动端点落到某条边的具体位置时，写 `port` 固定该端；
- 组内顺序变化（加/删线）会让其它线让位——这是可接受的（同边多线本就需要均分），
  文档写清。

### 7.4 悬停、连接点与 quick-add

基线（docs/08 §7）已满足，仅登记与 §7.1 的交互：

- 悬停 widget 显示四边连接点（外移 24 屏幕 px）；选中形状常显；
- 从连接点按下 = 建线跟随，位移 < 4px 松手 = quick-add（连线 + 默认矩形）；
- 端点重锚定时用 `nearestJoin`（归一化象限）+ 投影 `t` 写 `{join, port}`；
- M-03/M-04 的文档改写：删除 `getAnchorsData()` 说法，改为 `getHostGeom()` +
  `getAnchorPoint()`；hover 口径统一写「四向外移点最近」，删除「大节点按象限精确方向」
  的误导表述（象限选择只用于重锚定判定）。

### 7.5 自环（G-07 / M-02）

**决定：保留并显式化紧凑自环，改写 docs/08 §7。**

- 触发：`startNodeId === endNodeId !== null`。
- 新增 `routeSelfLoop({ start, end, startJoin, endJoin, node })`（`lineRoute.ts`）：
  - 同 join（top→top）：从锚点沿法向外扩 `NODE_MARGIN`，横向跨度
    `max(80, node.width × 0.5)`，输出 U 形；
  - 异 join（top→bottom）：外扩后走节点外侧（左/右取距两锚点更近的一侧），输出矩形环；
  - 全部线段轴对齐、不自交；
  - 路由优先级：`pinned` 用户手滑 > 自环 > 常规 `routeElbow`。
- 创建路径：从 A 拖回 A（同边或不同边）→ 线保留并落 `{...A, ...A}`；`settle` 的距离
  判据（4px）不变，只把「同一 widget」从「删除」改为「自环」。
- 编辑：端点可重锚定；一端解绑 → 退化断头线（§7.6）；删除 A → `unbindFrom` 两侧同置
  null（现有实现天然覆盖）。
- 箭头/文字/段滑移在自环上必须可用（U 形为 4 段以上折线，段语义成立）。
- 测试：top→top、top→bottom、right→right、1 步撤销、PNG 导出含自环。

### 7.6 解绑与断头线（G-09）

现状：删除节点只把线端 `nodeId/join` 置 null，points 不动（一个撤销单元），
无提示、无清理入口。

目标：

- 保留默认解绑语义（零回归，不擅自级联删除用户数据）；
- 新增命令 `pruneDanglingLines(): number`：删除「恰好一端 `nodeId === null`」的线
  （单事务、可撤销、返回条数）。纯自由线（两端均 null）不清除——它是合法图元。
- UI：画布空白右键菜单追加「清理悬空连线」，无匹配项时 disabled；
- 只读态：命令层守卫 + 菜单项禁用（docs/21 §4 双层）；
- 已知取舍：刻意画的「一端悬空」线会被清掉。文档在 docs/08 §3 写清判定口径。

## 8. 路由层

### 8.1 正交候选走廊（既有，不改）

见 docs/08 §4：三级走廊（30/60/90）、候选交点 + 中线走廊、穿模过滤、择优
（不穿节点 > 拐点最少 > 总长最短）、`mergeCollinear`、`absorbTinyJogs`、
`MIN_ANCHOR_APPROACH = 20`、`ELBOW_RADIUS = 14`。本阶段不动这些口径。

### 8.2 全局避障（G-06）

现状：`routeElbow` 的障碍集合恒为 `[startNode, endNode]`，第三条节点挡在中间时线
直接穿过（实测：A→B 直线穿过中间 C）。

目标：

```ts
// lineRoute.ts
export interface IRouteElbowOptions {
  // ...既有字段
  /** 第三方障碍（世界 AABB）：只参与穿模过滤，不参与走廊生成；首末段豁免仍只对
   *  startNode / endNode 生效 */
  obstacles?: IRect[];
}
```

调用方（`LineAnchorFollow.routeLinePoints`）收集：

1. 包围盒 = `start`/`end` 两点外扩 `OBSTACLE_PAD = 120`；
2. 取 `vmEngine.getVmsInRect(包围盒)`，排除 LINE / PEN / 两端节点自身；
3. 用 `rotatedRectBounds(getHostGeom())`（旋转件保守外接），按「与两端中点距离」
   升序取前 `MAX_OBSTACLES = 32`；
4. `pinned` 分支不避障（用户手滑优先）。

约束：

- 先正确后性能：候选过滤是 `候选数 × 段数 × 障碍数`，实测超 §15 预算再引入
  「按走廊带裁剪障碍」（只留与候选路径 AABB 相交的障碍）；
- 全候选挡死 → 保持既有 fallback（首候选），不得抛错/返回空；
- 视觉回归：既有 E2E 全绿、5 张视觉基线（darwin / linux 各一份）逐字节不变。既有场景
  多为相邻两节点连线，不受影响；受影响面只有「线本应避让却穿过」的样本。

### 8.3 退化与兜底

- 两端同轴对齐 → 直线；
- 端点重合（自环外的零长线）→ 端点重合判据走 `settle` 删除；
- 避障无解 → fallback 首候选（现状语义保留）。

## 9. 吸附与对齐层

### 9.1 参考线（既有，不改）

粘滞 + 方向过滤死区 + 边线↔中心线互吸 + 对齐/等距同轴最小偏差（specs/refline-snap-feel、
specs/spacing-endchain）。本阶段只新增「与网格吸附的优先级」一条。

### 9.2 网格吸附（G-08）

- 常量：`packages/core/src/common/grid.ts` → `GRID_SPACING = 16`（世界 px）。
  **与点阵背景同相位**：`dotGridMath.BASE_WORLD_SPACING = 16`，缩小时按 2 倍合并，
  点中心恒在 `x ≡ 0 (mod 16)`，故量化到 16k 落点正好压在点上，零视觉冲突。
  `@spinth/react` 的 `BASE_WORLD_SPACING` 改为从 `@spinth/core` re-export，消双源。
- 量化 API：`quantizeGrid(v)`（`Math.round(v / 16) * 16`）、`quantizeGridRect`。
- 开关：`gridSnap` 板级偏好（默认 **关**），会话态 + `localStorage` 持久化（视图偏好，
  不进 Yjs、不进项目文件、不受只读态限制）；UI 入口 = 画布右键菜单项，勾选态经
  icon + label 表达（`MenuItem` 无 toggle 语义，值在菜单打开时定格），状态由新流
  `gridSnap$` 暴露。
- 应用点（全部落在「松手落库」与「同源预览」两处，禁止增量累加）：

  | 场景       | 量化对象                            | 备注                         |
  | ---------- | ----------------------------------- | ---------------------------- |
  | 拖拽移动   | 目标左上角                          | 多选以首个选区 bounds 为基准 |
  | 缩放       | 目标 rect（按被抓手柄的固定角对齐） | 不缩放子元素（无容器）       |
  | 拖拽创建   | 起止角                              | 单击创建量化左上角（§4.3）   |
  | 自由线端点 | 端点世界坐标                        | 已锚定端不量化（宿主决定）   |
  | 旋转       | 不量化                              | 角度无网格语义               |

- 预览与落库同源：预览输出即量化后几何（不会「松手跳一格」），最后一帧输出落库
  （渲染同步铁律 5），手势期仍零 Yjs 写。
- 与参考线优先级：**参考线先、网格后**——参考线命中则不量化（可见反馈优先），
  未命中才量化。顺序固定写在 `docs/05 §4.4`。

### 9.3 对齐 / 分布（既有）

6 向对齐 + 2 种分布，选中 ≥2/≥3 时可用；网格吸附不影响命令语义（命令走绝对几何）。

## 19. 手工验证步骤

> 结果记录（2026-11-14 返工收口）：以下 12 步为**待人工执行**清单——自动化等价物
> 已全部就位（F-1…F-8 + F-3b/c + F-6b/c/d + 视觉 S1 场景 + `pnpm verify`/
> `pnpm test:e2e`/`visual:linux --stability` 全绿），人工面聚焦手感与屏幕-导出
> 对照（§19.2 的 PNG 与屏幕逐像素对照无法自动化断言）。

1. `pnpm dev`，`r` 拖三个形状，分别设 stadium / rect / diamond。
2. ActionBar：填充 → 白；边框色 → 黑；边框宽 → 2；确认屏幕与 `导出画布 PNG` 一致。
3. 填充 → 无；确认仅剩描边、仍可选中拖动与连线。
4. `l` 连三条线到同一对边，观察均分；删中间一条，观察重新均分。
5. 在两个大形状中间放一个小形状，连线确认绕行；把中间形状挪到线外，确认恢复直连。
6. 从 A 的 top 拖回 A 的 bottom：确认生成自环；双击自环加标签；`⌘Z` 一步撤销。
7. 选中中间节点删除：线保留悬空 → 画布右键「清理悬空连线」→ 线消失 → `⌘Z` 恢复。
8. 右键勾「网格吸附」：拖形状观察落点吸到点阵；关掉后确认恢复自由。
9. 选中折线拖中间拐点：确认相邻段保持正交、不出现斜段。
10. ⌘0 归位、`f` 适应屏幕、导出 PNG 检查无裁切。
11. 只读模式（第二标签打开同一文档）：确认清理命令与画布编辑均禁用，视图项可用。
12. 旧项目文件导入：确认原图无变化、新面板显示缺省值。

## 21. 风险与回滚

| 风险                                 | 影响               | 缓解 / 回滚                                               |

   默认关 + 右键菜单**（localStorage 视图偏好）；入口迁工具坞未排期。
